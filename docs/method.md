# C/D 反馈方法

条件 C 和 D 共用 Python 输出优先的 renderer。Python 正文最多 1000 字符，整个反馈最多 2000 字符。截断标记计入预算。Trace 按原调用顺序填入剩余空间，日志区分筛选后选中的事件和完整可见的事件。

条件 C 对成功返回的工具事件取观察器保存的 `result_repr`。观察器对字符串保存原文，对其他返回值保存 Python `repr`。比较时折叠连续空白，保留大小写与标点。完整表示须达到最小字符阈值，并出现在截断后保留的 Python 正文中，才会筛掉对应事件。空值、短值、已截断的返回表示、形如 `<...>` 的不透明表示、异常和被拦截的调用均保留。D 关闭筛选。

方法日志分别记录筛选触发次数和筛选是否改变实际可见反馈。当筛掉的事件在 trace 截断点之后，这两个指标可能不同。最终反馈的字符数和 SHA-256 也随轮次保存。

## 本机验证

在仓库根目录运行 `python -m unittest discover -s tests -p test_selective_feedback.py -v`。

在 DEV v5 的 `message_decoder/specific_decoded_character` 中，条件 A 的第 2 轮已经显示 `reverse_string` 的完整返回。用同一份已记录的 Python 输出和事件调用 C/D renderer 时，默认 12 字符阈值的 C 省略了事件 1，反馈为 39 字符。D 保留该事件，反馈为 165 字符。此例验证规则触发和可见反馈变化。后续动作或任务成功率的变化需要用完整的 C/D DEV 运行评估。

研究方案登记的候选阈值为 12、24、48 字符。当前实现可通过反馈设置传入阈值，默认 12 字符。候选运行入口、实际 DEV 结果与冻结配置在后续交接补齐。
