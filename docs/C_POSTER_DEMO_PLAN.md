## Demo 流程（可按实际限时压缩）

1. 解释任务和四条件共同设置，指出唯一研究变量是反馈设计。
2. 打开一对真实保存轨迹，定位同一 task 的两个条件。逐步显示“工具实际产生什么”和“模型实际看到什么”，两者不能混淆。
3. 显示后续动作、最终结果和所有模型调用的累计 token；用逐任务表定位。
4. 展示审计状态、批次完整性和评分规则；解释一例失败/退步。
5. 回到研究问题，给出与正式结果一致的结论和局限。

准备核心短版（步骤 1–3）和扩展版（增加 4–5），不把内部设计时长写成课程规定。`docs/demo_walkthrough.md` 是 A 的历史平台草稿，含旧数据及早期资源数字，最终 demo 不直接照搬。

## 录屏/现场准备

- 在 DEV 确定演示流程和工具，不为展示在 EVAL 反复挑跑。正式结果出来后，从已有完整记录按案例规则选择；不新增“演示成功”替换正式结果。
- 如 TA 允许录屏，准备本地录屏和静态截图备份；如要求现场运行，预先核验环境，现场新跑结果与正式批次分开。
- 本地只需轨迹回放/文件展示和图表即可讲解，不假设现场能申请到 GPU。
- 展示数据不含私有参考文件、账号密钥；模型给出的 Answer 与离线 success 判定分开讲。
